# Glossary

Common DevRel, GTM, and developer-tools marketing terms, kept consistent across the library.

| Term | Meaning |
|---|---|
| **DevRel (Developer Relations)** | The function that builds and maintains high-quality connections between a technical product and its developers. |
| **GTM (Go-to-Market)** | How a product reaches and wins its target users — strategy, channels, and execution. |
| **Devtool** | A product aimed at developers (SDK, library, API, CLI, platform, infra). |
| **Positioning** | How a product is framed relative to alternatives — who it's for and the job it wins. |
| **Persona** | A named representation of the target developer: role, context, trigger, workaround. |
| **Messaging hierarchy** | One anchor message plus supporting pillars, each with proof. |
| **Content engine** | A repeatable pipeline that turns signals into published, multi-channel content. |
| **Channel mix** | The set of channels (HN, X, Reddit, docs, communities) and the job each owns. |
| **Launch cadence** | A timed checklist (e.g. T-14 → T+7) for shipping a version or feature. |
| **A/B test** | Comparing variants of a message or creative to see which converts better. |
| **Community listening** | Monitoring communities / social / issues to extract signals and intelligence. |
| **Signal** | A recurring observation (pain, ask, objection, praise) that implies an action. |
| **GTM funnel** | awareness → signup → activation → retention → advocacy. |
| **North-star metric** | The single metric that best captures the value a team delivers. |
| **Leading / lagging indicator** | Leading predicts outcomes (trial starts); lagging confirms them (retained users). |
| **Activation** | The moment a developer first gets value (first successful run / API call). |
| **Advocacy** | When users pull others in (referral, community answer, case study). |
| **Agent Skills** | An open skill spec: each skill is a `SKILL.md` with frontmatter, loadable and executable by AI agents. See https://agentskills.io. |
| **SKILL.md** | The Agent Skills spec file, containing `name` / `description` metadata and the instruction body. |
| **Progressive disclosure** | How agents load skills: name + description at startup → full SKILL.md on activation → bundled files on demand. |
| **skills CLI** | The npm CLI (`npx skills`) for installing and managing agent skills from GitHub repos. See https://skills.sh. |
| **Battlecard** | A concise comparison + objection-handling card for competing against a specific rival. |
| **DX (Developer Experience)** | How developers experience a product across its entire lifecycle. |
| **CC BY 4.0** | Creative Commons Attribution 4.0: free to reuse with attribution. |
