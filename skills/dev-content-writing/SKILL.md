# 开发者技术内容写作（Dev Content Writing）

## 何时使用
- 写技术博客、教程、Release 公告、社交媒体帖。
- 需要让「开发者」真正读完并行动。

## 核心原则
1. 先回答「这跟我有什么关系」再讲原理。
2. 代码示例可复制、可运行、有预期输出。
3. 用开发者语言，不堆营销词。
4. 每篇一个清晰结论或动作。
5. **先小测再放量**：大篇幅前，先用一条短帖 / 一个观点在讨论区验证是否被接受，再展开成正式文档。
6. **经验回流**：把「哪种语气 / 哪个角度被接受」记回 `references/voice-and-tone.md`，下次直接复用。

## 结构模板（博客 / 教程）
1. 钩子：一个具体痛点或「如果你也…」。
2. 上下文：为什么存在这个问题。
3. 方案：逐步 + 代码。
4. 验证：如何确认成功。
5. 收尾：下一步 / 相关资源。

## 标题公式
- 「如何用 X 解决 Y 的 Z 问题」
- 「X 入门：从 0 到跑通第一个示例」
- 「我们为什么弃用 X，转向 Y」

## 代码准则
- 标注运行环境与版本。
- 关键行加注释。
- 给出预期输出，减少「跑不起来」的挫败。

## 语气

## 发布清单
- [ ] 标题是否一眼懂价值？
- [ ] 代码是否复制即可运行？
- [ ] 是否有「下一步」引导？
