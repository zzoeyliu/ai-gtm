# 生态运营指标（DevRel Metrics）

## 何时使用
- 设定季度目标、向管理层汇报、评估运营投入产出。

## 核心原则
1. 一个北极星，不要十个。
2. 漏斗思维：认知 → 上手 → 采纳 → 贡献。
3. 指标服务于决策，不为好看而追踪。

## 北极星（示例）
- 对基础设施类项目：**周活跃采用者数**（真实在使用的人数）。
- 对社区类项目：**月度有效贡献者数**。

## 转化漏斗
| 阶段 | 指标 |
|---|---|
| 认知 | 曝光、Star、社媒触达 |
| 上手 | 文档访问、首次 clone、示例运行 |
| 采纳 | 生产使用、依赖引入 |
| 贡献 | Issue / PR、文档补丁、答疑 |

## 分层 KPI
- **增长**：新用户 / 新贡献者增长率。
- **参与**：活跃讨论数、首响时长。
- **健康**：Issue 关闭率、贡献者留存。

## 数据来源
- GitHub API：Star / Fork / Issue / PR。
- 社媒后台：触达 / 互动。
- 文档分析：访问 / 搜索词。

## 汇报节奏
- 周：信号与异常（见 `community-weekly-report`）。
- 月 / 季：漏斗变化与目标达成。

## 常见误区
- 把 Star 当采纳（Star ≠ 使用）。
- 追踪没人看的指标。
- 目标过多导致失焦。
