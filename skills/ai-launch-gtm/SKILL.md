# AI Launch GTM / AI 产品发布 GTM

## When to Use / 使用场景

- **EN**: A team is shipping a version, feature, or campaign and needs a repeatable GTM playbook. Growth depends on one-off posts instead of a planned channel mix. You want to test messages across channels without burning the whole audience.
- **中文**：团队要发布版本、功能或活动，需要可复用的 GTM 打法。增长靠零散发帖而非有计划的渠道组合。希望跨渠道测试信息，又不把受众一次耗光。

## Core Principles / 核心原则

1. **Launch runs on demo + value + hands-on / 发布靠演示+价值+可上手**, not slogans. / 不靠口号。
2. **Each channel owns a job / 每个渠道各司其职**: HN for credibility, X for reach, 小红书 for discovery, Product Hunt for early adopters. / HN 立可信度，X 拉触达，小红书做种草，Product Hunt 抓早期用户。
3. **The first 48h are the golden window / 首发 48 小时是黄金窗口** — someone must be present. / 必须有人在线应答。
4. **Small test before full push / 先小范围测试再全力推** — validate with a warm-up post or core-user preview. / 用预热帖或核心用户预览先验证。
5. **Feed experience back / 经验回流** — record what worked for direct reuse. / 记录有效打法以便复用。

## Procedure / 操作流程

1. **Goal / 目标**: pick one objective (signups / activation / a specific feature adoption). / 选定一个目标（注册/激活/某功能采用）。
2. **Message / 信息**: pull the relevant pillar from the positioning hierarchy. / 取定位层级中对应支柱。
3. **Channel plan / 渠道计划**: assign each channel a role and a format. / 给每个渠道分配角色与形式。
4. **Demo / 演示**: ship one reproducible example that proves the claim. / 交付一个可复现、能证明主张的演示。
5. **Launch / 发布**: T-0 tag/release + announcement + social; staff the Q&A window. / 发布+公告+社媒，并值守问答。
6. **Experiment / 实验**: run 2–3 message variants via AI-assisted A/B on the same channel. / 同渠道用 AI 辅助 A/B 跑 2–3 个变体。
7. **Retro / 复盘**: capture what converted, what wasted, and the follow-ups. / 记录转化、浪费与后续动作。

## Templates / 模板

### Channel mix / 渠道组合

| Channel / 渠道 | Job / 角色 | Format / 形式 |
|---|---|---|
| Hacker News | Technical credibility / 技术可信度 | Result + method, no hype |
| X / Twitter | Reach + narrative / 触达+叙事 | Insight thread, demo clip |
| LinkedIn | Decision-makers / 决策者 | "Why this matters" framing |
| 小红书 | Discovery / 种草 | First-hand experience note |
| 视频号 | Reach in China / 国内触达 | 60s demo + spoken takeaway |
| Product Hunt | Early adopters / 早期用户 | Launch page + maker comment |
| Dev communities | Deep users / 深度用户 | Discussion, Q&A, feedback |

### Launch timeline / 发布时间线

| Time | Action / 动作 |
|---|---|
| T-14 | Goal + message; draft announcement / 目标+信息；起草公告 |
| T-10 | Reproducible demo; internal review / 可复现演示；内部评审 |
| T-7 | Finalize release note; pre-write social variants / 定稿发布说明；预写社媒变体 |
| T-3 | Core-user preview; set launch-day monitoring / 核心用户预览；设发布监控 |
| T-0 | Tag/release + announcement + social; community sync / 发布+公告+社媒；社区同步 |
| T+1–2 | Golden Q&A window: staff comments and DMs / 黄金问答窗口：值守评论与私信 |
| T+7 | Retro: data, feedback, follow-ups / 复盘：数据、反馈、跟进 |

### A/B variant brief / A/B 变体简报 (for AI)

> Generate 3 launch posts for [feature] on X. Variant A leads with speed, B with cost, C with a concrete user story. Keep each under 280 chars. No superlatives.
> 为 [功能] 在 X 上写 3 条发布帖。A 主打速度，B 主打成本，C 主打具体用户故事。每条 280 字以内。不用最高级。

## Gotchas / 常见陷阱

- **Never announce a date before the release note is final / 发布说明没定稿前别定发布日.** Scope creep is the #1 cause of missed launch days. / 范围蔓延是跳票头号原因。
- **A demo that only works on the author's machine is a launch-day bug / 只作者本机能跑的演示是发布日事故.** It must run from a clean checkout. / 必须干净环境可复现。
- **The 48h window needs a named owner / 48 小时窗口要有具体负责人**, not "the team". / 别用「团队」模糊责任。
- **Spamming communities with launch links burns trust / 在社群硬发链接永久损耗信任.** Answer the question; mention the product only when it's the answer. / 先答问题，产品只是答案时才提。
- **Don't A/B test more than one variable at a time / 一次只测一个变量.** One variable, clean read. / 单一变量，干净读数。
- **Capture day-zero data on launch day / 发布当天就采集首日数据.** You can't reconstruct it later. / 日后无法补采。

## Checklist / 自检清单

- [ ] Is there one launch objective (not "awareness")? / 是否只有一个发布目标（而非「曝光」）？
- [ ] Does each channel have a distinct job and format? / 各渠道是否角色与形式分明？
- [ ] Is there a named owner for the T+0 to T+2 window? / T+0 至 T+2 是否有具名负责人？
- [ ] Is the demo reproducible from a clean checkout? / 演示是否干净环境可复现？
- [ ] Is day-zero data capture scheduled? / 是否安排了首日数据采集？

## Shared Context / 共享原则

- Outcomes over output: we measure whether users adopt and convert, not whether they liked the post. / 重结果而非产出。
- Evidence-based: cite real signals and proof; never invent metrics or claims. / 基于证据，绝不编造。
- Audience respect: no hype, no fake "best", no jargon without translation. / 尊重用户，不炒作、不编造、黑话必译。
- AI is a lever, not autopilot: AI drafts and analyzes; a human owns the message and the judgment. / AI 是杠杆不是自动驾驶。
- Client confidentiality: protect client data and unreleased plans. / 客户保密。
